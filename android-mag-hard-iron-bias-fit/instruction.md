I work on the Android factory line calibrating magnetometers. Every phone has small magnets inside from speakers and screws that add a constant offset to the magnetic sensor. We call it hard iron bias. During factory test we rotate the phone in a full figure eight and log raw magnetic field values from the sensor.

The physics is straightforward. Without any internal offset, the earth field as seen by the phone is a vector with basically fixed magnitude but direction changes as the phone rotates. So all readings would sit roughly at the same distance from zero, in the range about 35 to 60 uT. With internal offset, the whole point cloud is shifted by an unknown vector. Each raw reading is earth direction times strength plus bias plus some noise.

I need you to build a small tool for me. Please create a file at /app/mag_calibration.py. Inside that file create a function named estimate_hard_iron_bias. It should take one argument which is a numpy array of shape N by 3. Each row is mx my mz in uT. N is at least 50 and can be up to 10000. The function should return a dict with four keys. bx is bias on X axis, by is bias on Y, bz is bias on Z, radius is estimated earth field strength. All values must be float and radius must be greater than zero. Make the dict JSON serializable so not numpy scalars.

The data you will get is messy in ways the production line actually sees. It can have Gaussian noise up to std 2.0 uT. The figure eight is often incomplete because operators stop early, so angular coverage can be as low as 30 percent of the full orientation sphere. Density is also not uniform, the rig dwells longer at the ends of the figure eight. It can also have up to 7 percent outliers that are far from the true cloud due to motor spikes. Occasionally a channel saturates and reports NaN or Inf for a sample, up to about 2 percent of rows, those rows should be ignored. Radius is unknown but expected in range 25 to 65 uT. Bias components are in range negative 80 to 80 uT.

You need to estimate bias and magnitude from the cloud alone. Do not hardcode bias or radius, hidden data uses random values different from any sample file. The estimator must be robust to the partial coverage and density variation and to the far spikes and to the NaN or Inf rows. Factory needs consistent accuracy under all these conditions.

You can test locally on sample file at data/sample_orbit.csv which has 500 points, bias about 15 negative 20 8, radius about 45, noise std 0.5. The test system generates its own hidden data and directly calls your function, so do not rely on file paths inside the function. Hidden data use random bias up to plus minus 80, random radius 28 to 62, random N 200 to 2000, random noise up to 2.0, coverage 0.3 to 1.0, outlier ratio up to 0.07, plus occasional NaN or Inf rows.

Only use numpy and standard library. Do not import scipy, sklearn, torch etc. Function must be deterministic given same input. Handle degenerate inputs gracefully but you may assume valid data after dropping bad rows has at least 50 points and not all coplanar.
