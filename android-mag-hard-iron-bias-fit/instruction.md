I work on the Android factory line calibrating magnetometers. Every phone has small magnets inside from speakers and screws that add a constant offset to the magnetic sensor. We call it hard iron bias. During factory test we rotate the phone in a full figure eight and log raw magnetic field values from the sensor. The metal chassis also causes soft iron scale distortion where each axis is stretched by a few percent.

The physics is like this. Without any internal offset, the earth field as seen by the phone is a vector with basically fixed magnitude but direction changes as the phone rotates. So all readings would sit roughly at the same distance from zero, in the range about 35 to 60 uT. With internal offset, the whole point cloud is shifted by an unknown vector. With soft iron scale, the cloud is also stretched into an ellipsoid rather than a perfect sphere. Each raw reading is S times earth direction times strength plus bias plus some noise, where S is diagonal scale diag sx sy sz.

I need you to build a small tool for me. Please create a file at /app/mag_calibration.py. Inside that file create a function named estimate_hard_iron_bias. It should take one argument which is a numpy array of shape N by 3. Each row is mx my mz in uT. N is at least 50 and can be up to 10000. The function should return a dict with four keys. bx is bias on X axis, by is bias on Y, bz is bias on Z, radius is estimated earth field strength. All values must be float and radius must be greater than zero. Make the dict JSON serializable so not numpy scalars.

The data you will get is messy in ways the production line actually sees. It can have Gaussian noise up to std 2.0 uT. The figure eight is often incomplete because operators stop early, so angular coverage can be as low as 30 percent of the full orientation sphere. Density is also not uniform. The rig dwells longer at the ends of the figure eight, so about 60 to 70 percent of points are clustered in two tight lobes at the ends where the rig pauses, and there is extra motor magnetic interference up to about 0.7 uT std when dwelling. The metal chassis causes soft iron scale sx sy sz each in range 0.85 to 1.15, so points lie on an ellipsoid not a sphere. It can also have up to 7 percent outliers that are far from the true cloud due to motor spikes. Occasionally a channel saturates and reports NaN or Inf for a sample, up to about 2 percent of rows, those rows should be ignored. Radius is unknown but expected in range 25 to 65 uT. Bias components are in range negative 80 to 80 uT. Scale components are in range 0.85 to 1.15.

You need to estimate bias and magnitude from the cloud alone despite ellipsoid distortion and density variation. Do not hardcode bias or radius, hidden data uses random values different from any sample file. The estimator must be robust to the partial coverage, to the non uniform dwell density with motor interference, to the soft iron ellipsoid stretch, to the far spikes and to the NaN or Inf rows. Factory needs consistent accuracy under all these conditions. A plain textbook sphere fit that assumes uniform density and perfect sphere will fail on dwell plus soft iron cases.

You can test locally on sample file at data/sample_orbit.csv which has 500 points, bias about 15 negative 20 8, radius about 45, noise std 0.5, no soft iron. The file will also be available at /app/data/sample_orbit.csv in the evaluation image. The test system generates its own hidden data and directly calls your function, so do not rely on file paths inside the function. Hidden data use random bias up to plus minus 80, random radius 28 to 62, random N 200 to 10000, random noise up to 2.0, coverage 0.3 to 1.0, outlier ratio up to 0.07, soft iron scale 0.85 to 1.15 on some tests, dwell ratio 0.0 to 0.65 with motor interference up to 0.7, plus occasional NaN or Inf rows.

Only use numpy and standard library. Do not import scipy, sklearn, torch, pandas, cv2 etc. Do not use eval, exec, compile, __import__. Function must be deterministic given same input. Handle degenerate inputs gracefully but you may assume valid data after dropping bad rows has at least 50 points and not all coplanar.
